# DSS v2 sensitivity audit and revision

## Root cause: historical gate, not MAE

The old policy compared smooth forecast expectations to thresholds calibrated
on extreme individual actual days. It required z >3.829081 for weekdays and
>3.455279 for transitions. Across the already-inspected 255 holdout origins,
the largest forecast z was only 1.731879. Removing MAE alone would change nothing.

| Gate, before revision | Count |
|---|---:|
| Potential comparisons (7 weekdays + 6 adjacent transitions per origin) | 3,315 |
| Insufficient historical support | 38 |
| Supported comparisons | 3,277 |
| Passing historical threshold | 0 |
| Passing MAE scale independently | 136 |
| Passing both gates | 0 |
| Returned operational advisories | 0 |

All 136 independent MAE passes were weekday comparisons; no transition passed
the sum-of-MAEs gate. Raw candidate comparisons are not detected anomalies.

|---|---:|---:|---:|---:|
| Absolute forecast deviation, guests | 0.051 | 13.842 | 37.631 | 52.179 |

| Old historical z threshold | 3.45528 | 3.82908 | 3.82908 | 3.82908 |

The full gate audit is `artifacts/dss_v2/sensitivity_audit.json`, generated by
`python scripts/audit_dss_sensitivity.py`. It always uses the archived original
policy from `artifacts/dss_v2/calibration.json`, not the current policy.

## Changed behavior

The active `weekday-insight-advisory-v2` rule returns **Demand Insights** describing
quantitative expected differences from causal same-weekday references. They have
`category=DEMAND_INSIGHT`, `priority=INSIGHT`, `recommended_action=null` and response
`state=INSIGHTS`. These are not declarations of realized anomalies, confidence,
or staffing needs. A forecast may differ meaningfully from its reference while
remaining inside normal daily variability.

MAE remains truthful internal error-scale context, not an arbitrary binary gate
on descriptive comparisons. Missing MAE does not prevent a supported descriptive
comparison. No confidence percentage is inferred from MAE. Strong operational
advisories and transition actions are disabled in the revised policy: neither
historical-reference calibration nor the development probe validates interventions.
The original advisory rule is retained for baseline regression testing.

Historical support rules remain 42/56, six weekday observations, with a causal
112-day fallback requiring 84 overall and ten group observations. Missing/NULL
days are never imputed. Only dates through the model-specific latest label date
enter references. Strict HIGH/NORMAL/LOW tiers and all ML predictions are unchanged.

Rank descriptive insights by z / insight threshold, then guest deviation and
deterministic date/signal ties. Deduplicate by signal direction and date, so the
section shows at most one above-reference and one below-reference day. This
avoids repetitive cards without forcing a nonempty response. Neutral comparisons
still return an empty list. React only renders the API's category, title, date,
evidence and optional action; it contains no decision calculations or quality badges.

## Development/validation evidence and its limits

Reproduce with `python scripts/validate_dss_sensitivity.py`. No saved model is
retrained or modified. The saved models were selected using data through May 2017;
their aggregate metrics do not contain development forecast rows. Replaying their
final parameters before selection would leak information. Instead this experiment
uses an explicitly labeled **causal historical level probe**:

`probe forecast = max(0, same-weekday mean + mean(last 14 valid calendar days) - mean(last 56 valid calendar days))`

The 14-calendar-day window requires ten COMPLETE observations. The probe shares
the smooth recent-level structure of the deployed models but is **not a replay or
validation of those models**. Its purpose is to test a descriptive context policy.
All inputs end at the origin, with targets at horizons 1–7. Only COMPLETE targets
are scored. Calibration targets end June 30, 2016 (1,553 comparisons); validation
origins start July 1, 2016, and all targets end by May 31, 2017 (1,610 comparisons).

The explicitly defined historical anomaly event is an absolute realized target
departure from the causal same-weekday reference greater than one historical sample
SD. FPR is `alerts on non-events / all non-events`; matching direction is reported
separately. This event definition is statistical, not operational ground truth.

Candidate z thresholds are calibration quantiles .75, .85, .90, .95 and .975.
The selection criterion, encoded before evaluation, maximizes detection subject
to validation FPR <=10% and latest-known-day deletion flips <=5%. These are explicit
descriptive-screening engineering budgets, not significance levels or guarantees.
No minimum number of returned insights is imposed. The selected threshold is
**0.6498651321** (calibration .75 quantile).

|---|---:|

## Locked-policy descriptive holdout comparison

The revised policy was written before running `python scripts/backtest_dss.py`.
However, the existing holdout was already inspected during the original audit.
These are **descriptive results on a previously inspected holdout**, not a fresh
unbiased test. No thresholds were changed after these results were observed.

| Model | Origins | Before: advisory origins | After: insight origins | After: cards | Reference-deletion-changed origins |
|---|---:|---:|---:|---:|---:|
| imputed_canonical_history | 85 | 0 | 82 | 94 | 8 |
| imputed_imputed_history | 85 | 0 | 84 | 102 | 5 |
| causal_causal_history | 85 | 0 | 83 | 99 | 5 |

All revised cards are descriptive Demand Insights; operational advisory count
remains zero. Frequent descriptive output is not proof of useful anomaly prediction.
Results are in `artifacts/dss_v2/sensitivity_holdout.json`, including unscorable
partial actuals and direction/tail proxies. The tail proxy there uses the insight
threshold, so it must not be confused with the one-SD validation event or its FPR.
Model files and notebooks are hashed before/after the backtest and remain unchanged.

At August 24 the causal model now highlights Friday **165.8 vs 136.0 (+21.9%)** and
Monday **148.6 vs 168.9 (-12.0%)**. These are API-calculated expectation comparisons,
with no staffing action. All 53 valid reference days are still available internally.

## Verification and modified files

Verified results: **42 backend/model/DSS tests passed**, **10 frontend client/geometry
tests passed** including live API access, frontend production build passed, and
browser checks passed for all three daily models at 1440px/390px CSS widths.
The live August 24 view rendered two API-provided descriptive cards for each model.

Changes cover `decision_rules.py` (descriptive stage/deduplication),
`recommendation_service.py` (policy validation/state), `policy.json`, the additive
API schema, and `OperationalDecisionSupport.jsx` (category and optional action).
Audit/validation/backtest scripts and their JSON evidence are included. Backend
tests distinguish original advisory regression from the revised descriptive rule;
integration tests compare exact saved prediction values and strict tier output.
The browser test checks API evidence/category rendering for all models at desktop
and mobile widths, plus separate presentation fixtures.

Run backend verification with `DWDSS_INTEGRATION=1` and
`PYTHONPATH=.;tests/warehouse;tests/pipeline`: `python -m pytest tests/dss tests/ml tests/backend -q`.
Run client checks with `DWDSS_API_BASE_URL=http://localhost:8000`:
`node --test frontend/tests/*.test.mjs`; build with `npm --prefix frontend run build`.

Overlapping windows are dependent, policy selection used validation, and historical
publication timing is assumed. Actual saved-model pre-selection prediction rows,
a new untouched evaluation period, and operational outcome data are still needed
before claiming calibrated predictive advisories or business impact. No ML models,
forecasts, canonical targets, DW/Mart, ETL or notebooks were changed. No commit or push.
